## [Rust 1.100 stabilizes never type, custom allocators, and Cargo cooldowns](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100 was released on November 12, 2026, stabilizing the never type (!) and custom allocators in the language, alongside several major Cargo changes. Cargo now supports configurable minimum publish ages (dependency cooldowns, per RFC 3923), warns about unused dependencies by default, and makes `cargo install` use the lockfile shipped inside the .crate tarball, turning `--locked` into a no-op. Two long-running language features finally landing — the never type and custom allocators — remove long-standing limitations for code that relies on diverging expressions or needs specialized memory management. The Cargo cooldown feature is arguably the most impactful for the wider ecosystem, since it gives every Rust project an opt-in defense against supply-chain attacks that push malicious updates shortly after publishing. When the cooldown config is set, the resolver ignores crate versions published more recently than the configured age, unless that version is already pinned in Cargo.lock; the unused-dependency check is controlled by the `cargo::unused_dependencies` lint, set to `warn` by default. Reviewers also noted that the release stabilized APIs not covered in the blog post, such as `bool::toggle()`, `Box::map()`, and `str::trim_prefix()`/`trim_suffix()` and `Path::trim_prefix()`.

hackernews · mbStavola · Nov 12, 18:39 · [Discussion](https://news.ycombinator.com/item?id=50472038)

**Background**: The never type `!` is Rust's bottom type, denoting computations that never produce a value — such as `panic!`, an infinite loop, or a diverging function like `exit` — and values of type `!` can be coerced into any other type. Custom allocators let a program control how memory is obtained and released rather than always going through the global allocator, which matters for embedded systems, profiling, and performance tuning. Cargo is Rust's build and package manager, and dependency cooldowns are a supply-chain safeguard also appearing in other package managers: newly published versions are held back for a period so that a compromised or malicious release can be detected and yanked before it is widely adopted.

## [Apple Opens Foundation Models Framework to Developers, Including Free Private Cloud Compute](https://developer.apple.com/foundation-models-framework/) ⭐️ 8.0/10

Apple has published the Foundation Models framework, a native Swift API that gives developers direct access to the Apple Foundation Models running on-device and on Private Cloud Compute (PCC). The framework bundles built-in capabilities such as guided generation, tool calling, image understanding, and Dynamic Profiles, and Apple is offering PCC access at no cloud API cost to App Store Small Business Program developers with fewer than two million first-time App Store downloads. This turns Apple Intelligence from a system-level feature into a developer platform primitive, letting iOS and macOS apps add LLM-powered features without standing up their own inference infrastructure or paying per-token cloud bills. The free PCC tier in particular lowers the barrier for small indie developers, who can now run larger server-side models with longer context windows at Apple's expense. PCC eligibility is tied to App Store Small Business Program enrollment and a cap of two million first-time App Store downloads, and developers can test PCC features through TestFlight before shipping. Apple's third-generation AFM family consists of five models built in collaboration with Google, spanning on-device to server-based variants, and PCC itself relies on custom Apple silicon, a hardened OS, and stateless data processing to protect user data.

hackernews · kermatt · Nov 12, 21:13 · [Discussion](https://news.ycombinator.com/item?id=50474361)

**Background**: Apple Intelligence is Apple's umbrella brand for the generative AI features built into iOS, iPadOS and macOS, powered by the Apple Foundation Models (AFM) family. Until now those models were largely used internally by system features like Writing Tools and notification summaries rather than exposed as a public API. Private Cloud Compute is Apple's privacy-preserving cloud inference system, announced in June 2024, which extends the device's security model to servers so that requests too heavy for on-device hardware can be processed without Apple retaining user data. The framework's Swift API means developers can call these models with the same language they already use for app development, rather than integrating a third-party SDK.

## [smolmaxxing runs a 16B LLM on a 1st-gen iPad Air with under 1GB of RAM](https://github.com/hyperionaidev/smolmaxxing/) ⭐️ 8.0/10

A developer posting as mrashad74 has open-sourced "smolmaxxing," a project that achieves 16B-parameter LLM inference on severely memory-constrained legacy hardware — a first-generation iPad Air and a Xiaomi TV box, both with less than 1GB of usable memory — and reports "decent speeds given the hardware." The effort ships the custom kernels, the modified model weights (hosted on Hugging Face at huggingface.co/hyperionaidev), and the results needed to reproduce the work. It pushes the practical lower bound of what hardware can run a modern LLM, which matters for edge computing, offline/private inference, and reusing the enormous pool of low-RAM devices that would otherwise be e-waste. It also serves as a public stress test of how far quantization and hand-written kernels can stretch memory bandwidth on hardware that was never designed for this workload. Because even 4-bit weights for 16B parameters would need roughly 8GB, fitting the model into under 1GB of usable RAM necessarily relies on sub-4-bit quantization and/or streaming weights from storage rather than holding them resident — though the submitted summary does not spell out the exact scheme. The post also omits concrete tokens-per-second figures, so "decent speeds" remains unquantified until the repo's benchmarks are checked.

hackernews · mrashad74 · Nov 12, 15:23 · [Discussion](https://news.ycombinator.com/item?id=50468888)

**Background**: LLM inference is largely memory-bound: generating each token requires reading the model's weights, so the memory footprint and bandwidth of the device set the ceiling on speed. Quantization shrinks that footprint by storing weights at lower precision, typically INT8 or INT4 instead of 16-bit floats, trading a small amount of accuracy for far less memory and faster reads. Legacy tablets and TV boxes have a few hundred megabytes to about a gigabyte of usable RAM and no datacenter-class accelerator, which is why running a multi-billion-parameter model on them is normally considered out of reach. Custom kernels — hand-written low-level compute routines — are what let a project squeeze the remaining performance out of such unusual hardware.

## [22-Year-Old PostgreSQL Type-Confusion Primitive Chained into RCE (CVE-2026-6460)](https://mehmetince.net/part-3-6-how-i-ended-up-turning-a-22-year-old-postgresql-type-confusion-primitive-into-rce-cve-2026-6460/) ⭐️ 7.0/10

The exploit prepares a query using a composite type, alters one of that type's attributes before the prepared statement is executed, and thereby causes PostgreSQL to hand stale UUID bytes to code that treats them as a pointer. The finding matters most for managed and multi-tenant PostgreSQL services, where a single low-privileged database account could potentially be escalated into code execution on the underlying host without any superuser rights. It also exposes a long-lived architectural weak point in how PostgreSQL binds type identifiers to Datum values, which will likely inform hardening and auditing across the database ecosystem. According to the write-up and coverage, the attack requires only a low-privileged authenticated database user and no superuser access, but it does presuppose some form of database access, so its real-world scope is confined to shared-server and multi-tenant deployments. Commenters also note that in the classic sense it is closer to a privilege-escalation primitive from database access to host access than to a remotely reachable, unauthenticated RCE.

hackernews · ozirus · Nov 12, 18:22 · [Discussion](https://news.ycombinator.com/item?id=50471761)

**Background**: Internally, PostgreSQL represents every column value as a Datum, a tagged union that may hold either an inline value or a pointer, with the accompanying small integer type ID stored separately for efficiency. A type confusion occurs when the engine believes a Datum has one type while the underlying bytes actually belong to another, so the wrong interpretation of those bytes can corrupt memory. Composite types and prepared statements are standard PostgreSQL features that let clients define row-like structures and pre-plan queries for reuse, and the exploit abuses the window between preparing a statement and executing it.
