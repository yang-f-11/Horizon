## [Stop Using JWTs for Browser Sessions](https://gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) ⭐️ 8.0/10

A widely-circulated gist and community discussion argue against using JSON Web Tokens (JWTs) for browser-based user sessions, citing security and revocation problems. The debate clarifies that JWTs are suitable for service-to-service communication but not for client-side sessions. This matters because many web developers default to JWTs for authentication without understanding their limitations. Adopting session-based authentication with httpOnly cookies can improve security, reduce XSS risks, and simplify token revocation. JWTs are stateless and cannot be easily revoked once issued; they are designed for very short lifetimes (≤5 minutes). For browser sessions, stateful session IDs stored in httpOnly cookies provide better revocation control and are less susceptible to XSS attacks.

hackernews · dzonga · Jun 16, 16:49 · [Discussion](https://news.ycombinator.com/item?id=48558147)

**Background**: JWT is a self-contained token format that carries claims and is digitally signed. Unlike session-based authentication where the server stores session state, JWT verification requires only the token itself. However, this statelessness makes immediate revocation impossible without a blacklist. The debate contrasts stateless JWTs with stateful sessions, where session IDs are stored server-side and can be revoked instantly.

## [Slay the Spire 2 adopts custom deterministic PRNG for cross-platform seeds](https://tck.mn/blog/correlated-randomness-sts2/) ⭐️ 8.0/10

Slay the Spire 2 developers replaced the C# standard library's PRNG with a custom deterministic PRNG to ensure identical seeds across all platforms and prevent future-breaking changes from library updates. This guarantees that players on different platforms can share and experience the same seeds, enhancing community engagement and game longevity, while also protecting against seed breakage due to library changes. The custom PRNG is implemented directly in the codebase, avoiding platform-dependent behavior of C#'s System.Random. This prevents seeds from differing between desktop and mobile versions, a problem that occurred in the original Slay the Spire.

hackernews · rdmuser · Jun 16, 09:46 · [Discussion](https://news.ycombinator.com/item?id=48552844)

**Background**: A pseudorandom number generator (PRNG) is an algorithm that produces a sequence of numbers approximating randomness, but is deterministic given the same seed. In games, seeds initialize the PRNG to generate consistent outcomes like level layouts. If the PRNG implementation differs across platforms or changes over time, the same seed can produce different results, breaking seed sharing.
