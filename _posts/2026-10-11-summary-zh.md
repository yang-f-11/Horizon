## [DuckDB 2.0 为何更快：性能深入解析引发讨论](https://motherduck.com/blog/why-duckdb-20-is-faster/) ⭐️ 8.0/10

MotherDuck 发布了一篇题为《Why DuckDB 2.0 is faster》的博客文章，详细介绍了 DuckDB 2.0 带来的性能提升，包括递归 CTE 显著提速，以及查询代价不再按“轮数 × 表大小”计算，而是按“实际访问的行数”计算。该文在 Hacker News 上引发了大量讨论，涉及图扩展、新的 C++ 扩展 API 以及基于任务的并行执行等话题。 DuckDB 是目前使用最广泛的嵌入式分析数据库之一，项目方称其月下载量已超过 600 万次，因此一次带来全新执行与 I/O 模型的 2.0 大版本发布会影响庞大的数据分折师、Notebook 用户和工具开发者群体。这类性能改进能够显著改变图遍历、递归查询等分析型工作负载在笔记本或嵌入式数据管道中的运行速度。 根据文章及周边讨论，这些提速来自执行模型的重构——有读者指出 DuckDB 正在转向基于任务的并行执行，思路上接近 Umbra、CedarDB 等研究型系统，而不再是传统的“n 个线程加交换算子”模式。评论者还提到，新的 C++ 扩展 API 应能让扩展的开发和分发更快、更省力；同时 DuckPGQ 扩展已可用于图查询，这一点与文章重点宣传的递归 CTE 提速密切相关。

hackernews · tosh · Oct 10, 18:08 · [社区讨论](https://news.ycombinator.com/item?id=50035530)

**背景**: DuckDB 是一个开源的列式关系数据库，设计上与 SQLite 类似，以进程内嵌入方式运行，但它专注于在线分析处理（OLAP）而非事务型负载，面向在包含数十亿行的宽表上做快速聚合。查询优化器是数据库中决定如何执行某条 SQL 语句的组件，它需要在众多可能方案中做选择，因为同一条查询的执行时间可能从零点几秒到数小时不等。duckdb.org 上的一篇预览文章宣布 DuckDB v2.0 将于今年秋季发布，重点特性包括 DuckDB 作为服务器运行、触发器、VARIANT 类型、异步 I/O、新的 SQL 解析器以及新的存储格式。

## [小米开源全模态 MiMo-V2.6 系列，Pro 与 Flash 同步上线](https://t.me/zaihuapd/44323) ⭐️ 7.0/10

小米 MiMo 团队于 9 月 22 日宣布发布并开源 MiMo-V2.6 系列，包括定位旗舰的 MiMo-V2.6-Pro 和兼顾效率与成本的 MiMo-V2.6-Flash，两者均为原生全模态模型。面向高吞吐场景的 Pro-UltraSpeed 也在逐步推出，小米称其在同等质量下输出速度最高可提升 20 倍，目前网页体验、API 与 Hugging Face 模型入口均已开放。 这意味着小米 MiMo 团队把一套完整的开源原生全模态模型带入与头部闭源系统同台竞争的行列，降低了开发者构建智能体应用的门槛。对开源大模型与多模态社区而言，它让一家消费硬件厂商成为凭借全模态能力和推理速度（而不只是文本基准）参与竞争的可信玩家。 这些模型面向编程、电脑操作、3D 场景与视听内容创作等智能体任务，产品线将注重质量的 Pro、注重成本与延迟的 Flash，以及针对吞吐优化的 Pro-UltraSpeed 变体区分开来。20 倍加速是小米自述的同等质量下数据，公告并未提供公开基准或独立评测来验证这一说法。

## [红海冲突促使谷歌、Meta 启用伊拉克陆路光纤备用线路](https://restofworld.org/2026/google-meta-red-sea-subsea-cables-houthi-yemen/) ⭐️ 7.0/10

红海曼德海峡附近冲突升级，威胁着承载欧亚之间超过 90% 互联网流量的海底电缆，促使谷歌、Meta 和微软加快部署陆路备用线路。谷歌在 9 月以约 700 万美元购入两条沿土耳其国家管道铺设的光纤线路——据称这一价格是土耳其境内新建线路预期成本的 2 至 3 倍；谷歌和 Meta 已经开始通过伊拉克的陆路线路传输部分实际流量。 这一转变表明，单一狭窄咽喉要道上的地缘政治风险，足以迫使全球最大的网络运营商重新设计全球连接架构，可能推高欧洲、中东和亚洲数十亿用户的成本与延迟。由于谷歌、Meta、微软和亚马逊合计约占全球国际互联网带宽的四分之三，它们的路由决策实际上决定着公共互联网抵御地区冲突的能力。 海底电缆的成本仍远低于陆路线路，因此这些科技巨头依然把主要流量留在海底网络上，陆路线路主要被当作应急备份而非完全替代方案。微软另外宣布计划到 2030 年在中东的海底及陆路连接领域投资超过 4 亿美元；根据 TeleGeography 的数据，四家超大规模云厂商控制着约 75% 的国际带宽。

## [中国四部门拟禁止汽车配备全隐藏式门把手与折叠屏](https://www.news.cn/fortune/20261010/7f5fc9a7b3f145ca9e9da6c802c93b5e/c.html) ⭐️ 7.0/10

工信部等四部门发布新规征求意见稿，拟明确禁止车辆配备全隐藏式门把手，且不得采用折叠或柔性显示屏。根据该征求意见稿，自 2027 年 1 月 1 日起，创新设计未充分验证的新申报产品将不予公告；已公告车型须在 2027 年 7 月 1 日前补报验证材料，逾期且存在隐患的将被停产并实施召回。 新规将直接重塑全球最大汽车市场的车身外观与内饰设计方向，迫使车企和供应商放弃或重新设计那些已成为众多电动车标志性卖点的功能。由于中国生产和设计的车型大量出口全球，这一监管要求带来的设计与工程变更很可能传导至国际供应链和相关安全标准。 该征求意见稿设定的是硬性验证门槛而非指导性建议：环境适应性验证周期不得少于 1 年，整车可靠性试验里程不得低于 3 万公里，新申报车型还必须完成软硬件可靠性、结构及密封防护等全维度测试。已上市的不合规车型面临停产和召回风险，使得这些要求自 2027 年起具备真正的强制执行力。

**背景**: 全隐藏式（齐平式）门把手由特斯拉带火，随后被中国众多电动车企广泛采用，用于降低风阻并获得流线型外观，但也因事故或断电后救援人员和车内乘员难以找到或操作而遭到安全批评。折叠与柔性车载显示屏则是较新的趋势，可让屏幕收进仪表台或弯曲以贴合弧形内饰。工信部负责管理车辆公告目录，车型只有进入该目录才能合法销售，而此次征求意见稿正是要借助这一机制来阻止或撤销相关产品的准入。

## [巴黎法院裁定 Cloudflare 无需为 1.1.1.1 不封锁盗版站受罚](http://1.1.1.1/) ⭐️ 7.0/10

巴黎司法法院驳回了 Canal+ 的请求——Canal+ 曾要求对 Cloudflare 按每站每天 5 万欧元处以罚款。法院认定，Cloudflare 在法国仅通过其 CDN 封锁盗版体育直播站，而并未通过 1.1.1.1 DNS 解析器进行封锁；值得注意的是，这一结论依据的正是 Canal+ 自己提交的统计数据。 这一裁决对界定 DNS 解析器与内容封锁义务之间的边界具有重要意义，进一步支持了 Cloudflare 的立场：公共解析器属于中立的基础设施，而非内容把关者。它可能影响法国及其他欧洲法院今后如何看待针对基础设施提供商的 DNS 层封锁令，并改变版权方在寻求反盗版禁令时的施压空间。 Cloudflare 的透明度报告称，尽管存在法国和意大利法院的命令，公司至今并未通过 1.1.1.1 封锁任何内容，而仅通过 CDN 屏蔽，并向经过认证的权利人提供了一种可在数秒内中断盗播直播的机制。Canal+ 仍保留对该裁决提出上诉的权利。

telegram · zaihuapd · Oct 10, 15:06

**背景**: Cloudflare 运营着 1.1.1.1——一个 2018 年推出的免费公共 DNS 解析器，负责把域名转换为 IP 地址；与此同时，它还运营着负责缓存和分发网站内容的 CDN。由于 DNS 解析是一项底层且注重隐私的服务，它看到的是域名查询而非实际提供的内容，Cloudflare 因此主张自己并不具备审查解析器所查询站点的能力。法国付费电视广播商 Canal+ 等权利方此前已获得法院命令，强制中间商封锁盗版网站的访问，通常是通过 DNS 封锁，或要求 ISP 与 CDN 切断流量。本案检验的正是这类义务是否可延伸至公共 DNS 解析器，而非确实参与内容分发的 CDN。
