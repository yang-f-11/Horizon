## [Axiom Math Formalizes the Classification of Finite Simple Groups in Lean](https://cfsg.axiommath.ai/) ⭐️ 9.0/10

Axiom Math announced that it has formalized the Classification of Finite Simple Groups (CFSG) in the Lean proof assistant, hosted at cfsg.axiommath.ai. This makes it one of the largest machine-checked mathematical results ever completed, turning a theorem whose published proof spans tens of thousands of pages into a computer-verified artifact. CFSG is a foundational result in group theory whose original proof was spread across hundreds of journal articles by roughly 100 authors over five decades, so a machine-checked version sharply reduces the risk that a gap or a missing case goes unnoticed. It also stands as a flagship demonstration of how large-scale mathematical collaborations may be conducted with proof assistants in the future. The original classification states that every finite simple group is cyclic, alternating, of Lie type, or one of the 26 sporadic groups, and its proof history includes at least one case where mathematicians believed the work was finished only to discover a missing case. The formalization relies on Lean and its mathematics library mathlib, though the announcement page itself provides little detail on how much of the argument was verified versus assumed as axioms.

hackernews · pfdietz · Oct 27, 16:29 · [Discussion](https://news.ycombinator.com/item?id=50261647)

**Background**: A finite simple group is a finite group with no proper nontrivial normal subgroup — the analogue of a prime number for symmetry — and classifying all of them is a central achievement of 20th-century algebra. Lean is an open-source proof assistant and functional programming language, developed at Microsoft Research starting in 2013, in which proofs are written as code and checked by a small trusted kernel; its community-maintained library mathlib holds thousands of formalized definitions and theorems. Formal verification means encoding a mathematical statement and its proof so a computer can mechanically confirm every step, which is valuable precisely for results too large for any single person to check by hand.

## [Triton 3.9.0 ships atomic loads/stores and major backend changes](https://github.com/triton-lang/triton/releases/tag/v3.9.0) ⭐️ 8.0/10

Triton v3.9.0 was released, adding new `tl.atomic_load` and `tl.atomic_store` primitives (defaulting to acquire and release semantics respectively), a new `tl.atomic_poll` that waits on a pointer value and returns False on timeout, and `tl.fdiv(..., approx=True)` for fast FP32 division. The release also brings language-level conveniences such as chained comparisons like `0 <= x <= 8`, keyword-only parameters, tuple unpacking in list comprehensions, integer support in `tl.clamp`, plus compiler, Gluon/layout, AMD/HIP, NVIDIA backend and Proton profiling updates alongside documented breaking changes and deprecations. Triton is a core piece of AI/ML infrastructure — it underpins custom GPU kernel development and is the code-generation path used by frameworks such as PyTorch's Inductor backend — so changes to its frontend and backends propagate to a large downstream ecosystem of kernel authors and compiler integrators. Atomic memory primitives and a polling operation expand what synchronization patterns can be written directly in Triton, while the breaking changes mean downstream users must review their kernels before upgrading. Notable behaviour changes include E8M0 scale decoding, where `0x00` now decodes to `2^-127` and `0xFF` to NaN instead of zero and infinity, which alters results for kernels using those values, and a fix so that a forked child process no longer unloads GPU modules belonging to its parent. Compile time for deeply nested loops improved roughly 10x at nesting depth 8, several error classes now fail at compile time rather than silently, and `TRITON_INTERPRET=1` now matches compiled kernels for integer overflow, `tl.fma`, `tl.umulhi` and related ops.

github · warrendeng · Oct 27, 18:56

**Background**: Triton is an open-source language and compiler for parallel GPU programming that offers a Python-based environment for writing custom deep-learning compute kernels capable of running at high throughput on modern GPUs. Because it hides much of the low-level CUDA/ROCm plumbing behind Python-embedded DSL constructs, it is widely used to write fused attention, normalization and matrix-multiplication kernels, and it serves as a backend code generator for frameworks such as PyTorch/XLA and Inductor. The release notes also reference Gluon, Triton's lower-level programming model that exposes tensor layouts, shared memory and warp specialization directly for advanced kernels, and Proton, the lightweight profiler that ships with Triton for inspecting kernel metadata and hardware performance metrics.

This removes much of the burden of managing SSH keys, but it also ties VPN identity and SSH authorization together in one layer.

## [CPython's experimental JIT is being removed](https://lwn.net/SubscriberLink/1102102/0c00e4d550f25f8c/) ⭐️ 8.0/10

CPython's experimental JIT is being removed from the interpreter, after the Steering Council asked for a new PEP before the work could continue. The removal follows several releases of in-tree JIT development that had been positioned as part of Python's long-term performance plan. This eliminates the main in-tree route to speeding up pure-Python code and undercuts the hope that JIT gains would offset the single-threaded cost of free-threading. Python users who need raw speed will increasingly be pushed toward external options such as Cython, PyPy, or third-party JIT projects rather than the default interpreter. Commenters highlighted a structural obstacle: CPython's de facto C API effectively serves as the language's specification, so incidental quirks inherited from the historical implementation constrain what a JIT can safely assume, making a retrofit extremely difficult. Others noted that the JIT's incremental speedups were modest, and that the free-threading penalty it was partly meant to offset remains.

hackernews · f311a · Oct 27, 11:17 · [Discussion](https://news.ycombinator.com/item?id=50257419)

**Background**: CPython is the reference implementation of Python, and it traditionally executes bytecode in an interpreter loop instead of compiling hot code to native machine code the way JavaScript engines or PyPy do. A JIT (just-in-time compiler) watches which code paths run frequently and compiles them to machine code at runtime for speed. Recent CPython releases shipped an experimental JIT as part of a multi-release performance effort, developed alongside free-threading, which removes the Global Interpreter Lock so threads can run Python code in parallel at the cost of some single-threaded speed. Cython is a separate, long-standing tool that compiles Python-like source to C ahead of time, giving explicit rather than automatic speedups.

## [Google Research Proposes 'Sleep Framework' to Stop LLMs Forgetting](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/) ⭐️ 8.0/10

Google Research has proposed a 'sleep framework' for continual learning in which large language models periodically alternate between active interaction with users and offline 'sleep' consolidation phases that convert short-term context into long-term model parameters. The framework reportedly outperforms GPT-4 and supervised fine-tuning (SFT) baselines on tests involving 10-million-token contexts, continual translation, and mathematical reasoning. Catastrophic forgetting is a core obstacle to making LLMs learn continuously from new data after deployment, and a sleep-inspired consolidation cycle offers a concrete mechanism for models to acquire new knowledge without degrading what they already know. If it holds up beyond the reported benchmarks, it could shape how future models are updated and personalized in production rather than being retrained from scratch. The reported gains span 10-million-token long-context settings, continual translation, and math reasoning, with comparisons drawn against GPT-4 and SFT baselines. The source material is a brief summary without the full paper, so details on the number of sleep cycles, compute overhead of consolidation, and how parameters are updated are not yet publicly spelled out.

telegram · zaihuapd · Oct 28, 01:46

**Background**: Catastrophic forgetting (also called catastrophic interference) is the tendency of neural networks to abruptly lose previously learned information when trained on new data. Continual learning research tries to solve this so a model can keep accumulating skills across tasks instead of being retrained from scratch, with work on LLMs typically split into continual pre-training, instruction tuning, and alignment. The 'sleep' analogy comes from neuroscience, where offline consolidation during sleep is thought to replay and stabilize memories formed during the day.
