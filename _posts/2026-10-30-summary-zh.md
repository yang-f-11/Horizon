Mistral AI 于 2026 年 10 月 29 日发布了其旗舰模型 Mistral Large 4（绰号“Le Chonk”）的权重，距 API 预览版发布约三周；同时把 API 价格下调至预览版的一半左右——每百万输入 token 0.7 美元、每百万输出 token 2.1 美元，而此前分别为 1.36 美元和 4.18 美元。此次开放的模型采用 MoE 架构，总参数 1.05 万亿、激活参数 520 亿，配有 16 亿参数的视觉编码器和 100 万 token 的上下文窗口。 一家欧洲头部前沿实验室开放权重是行业大事，它为尤其是受数据主权约束的欧盟企业提供了可自托管、替代美国和中国前沿模型的选择。伴随而来的降价也让该模型首次在成本上具备真正的竞争力，可能促使企业把采购从竞争对手的 API 转向 Mistral。 该许可并非开源：任何经营“模型即服务”业务的一方，在将模型或其衍生作品用于商业用途前，必须与 Mistral 另行签署商业许可协议，社区成员认为称其为“开放权重”具有误导性。Mistral 还宣称该模型对恶意网络请求的平均拒答率为 96.6%，为开放模型中最高的，但有评论者指出，单看拒答率并不能说明模型对合法请求的有用程度。

## [H.264 为何如此高效：经典解析文章再获热议](https://sidbala.com/h-264-is-magic/) ⭐️ 8.0/10

一篇 2016 年的技术解析文章《H.264 Is Magic》近日在 Hacker News 上重新获得高热度，收获 356 分和 130 条评论，引发了对编解码器内部机制、x264、无损 H.264 以及 AV1/AV2 的详细讨论。这篇文章本身并非新突破，但它仍被广泛赞誉为解释 H.264 压缩为何如此高效的经典材料。 H.264 支撑着全球大量视频传输，因此清晰解释其技术技巧有助于工程师理解为何看似简单的压缩选择会产生巨大的实际影响。讨论还勾勒出向 AV1、AV2 等新编解码器过渡的进程，这对流媒体服务、浏览器厂商以及任何需要在画质、带宽和授权之间权衡的人都很重要。 文章剖析了 H.264 基于块、运动补偿和 DCT 的编码工具，说明许多小技巧如何组合成大幅码率节省。评论者补充说，H.264 确实有一种很少使用的无损模式，但通过工具很难发现，而且浏览器的支持并不一致。

hackernews · ea016 · Oct 29, 15:53 · [社区讨论](https://news.ycombinator.com/item?id=50291054)

**背景**: H.264 也称为 AVC 或 MPEG-4 Part 10，是一种广泛部署的视频压缩标准，基于面向块的运动补偿编码。编解码器是压缩和解压某种视频格式的软件或硬件组件，而 H.264 广泛的硬件支持使其成为流媒体、广播和录制领域的默认选择之一。x264 是知名的 H.264 软件编码器，在讨论中被作为深度编码器优化的例子。AV1 等较新格式则旨在比 H.264 和 HEVC 进一步提高压缩效率。

## [PHP2Shell 与 Linux XFRM 漏洞串联利用，攻陷 25 台服务器（含美国政府系统）](https://dreamgroup.com/blog/chained-php2shell-exploit-roots-25-servers) ⭐️ 8.0/10

Dream 发布的一份事件报告披露，攻击者将面向 Web 的 PHP2Shell 远程代码执行漏洞与 Linux 内核 XFRM ESP-in-TCP 子系统中的提权漏洞串联利用，最终在 25 台服务器上取得 root 权限，其中部分服务器属于美国政府系统。报告逐步还原了完整的攻击链路，从最初的 Web 利用、内核层提权一直到在整批被攻陷主机上维持 root 持久访问。 这起事件表明，单个未修补的 PHP 应用不再是一个孤立问题：攻击者一旦落地到主机上，一个默认启用的内核特性就可能把 Web 层代码执行升级为完整的 root 沦陷。由于受害者中包括政府系统，该报告很可能加大 PHP 应用维护者与 Linux 发行版双方的压力，促使它们重新审视哪些网络子系统应当默认开启。 报告详细描述了攻击链的各个阶段，其中包括早期使用的一个约 383MB 的内存耗尽步骤（A1）；其取证细节——一段逐字照搬的 PAN-OS 配置项，以及与真实部署相符的 SELinux 配置——让评论者认定该防火墙厂商是 Palo Alto Networks。攻击链中的内核侧漏洞属于 ESP-in-TCP/XFRM 这一类缺陷，同类问题中已有公开记录的包括 CVE-2026-46300（代号“Fragnesia”，一种本地提权漏洞，已有公开 PoC、且不依赖竞争条件）以及 CVE-2026-80846。

hackernews · 882542F3884314B · Oct 29, 10:42 · [社区讨论](https://news.ycombinator.com/item?id=50286987)

**背景**: PHP2Shell 指的是一对高危害的 PHP 内存安全漏洞（CVE-2026-109618 与 CVE-2026-109619），影响 PHP 5.4 至 8.5 版本，可通过 session.upload_progress 回调等机制实现远程代码执行，使攻击者取得 Web 主机的控制权。内核方面，XFRM 是 Linux 的 IPsec 框架，而 ESP-in-TCP（RFC 8229）将 IPsec 的 ESP 数据包封装在 TCP 之中，以便 VPN 流量穿越 NAT 和受限网络；该数据包处理路径上的缺陷可被本地利用以提升至 root 权限。将两者串联，意味着 Web 层的一个立足点会被转化为同一台机器上内核级的最高权限。
