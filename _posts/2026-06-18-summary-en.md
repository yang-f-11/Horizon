## [RFC 10008 Proposes New HTTP QUERY Method for Safe Queries with Body](https://www.rfc-editor.org/info/rfc10008/) ⭐️ 8.0/10

RFC 10008, published on 27 May 2025, defines a new HTTP QUERY method that is safe and idempotent, allowing a request body for query parameters, addressing limitations where GET cannot have a body and POST is not idempotent. This is the first new HTTP method in years, with significant implications for web APIs, caching, and HTML forms—enabling cacheable, idempotent queries with complex payloads without the side-effect risks of POST. The QUERY method is safe and idempotent, meaning it has no significant side effects and multiple identical requests produce the same result. Caching strategies for QUERY may include comparing request bodies bitwise.

hackernews · schappim · Jun 17, 10:51 · [Discussion](https://news.ycombinator.com/item?id=48568502)

**Background**: HTTP defines methods like GET (without body) and POST (not idempotent). Developers sometimes needed to send a request body for queries, leading to workarounds like using POST or sending body with GET, which caused interoperability issues. The IETF working group decided to create a new QUERY method to standardize this pattern.
