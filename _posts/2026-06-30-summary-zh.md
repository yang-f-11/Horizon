## [最高法院裁定地理围栏搜查令需受第四修正案保护](https://www.theguardian.com/us-news/2026/jun/29/supreme-court-geofence-warrants-case-decision) ⭐️ 9.0/10

美国最高法院裁定，允许执法部门获取特定区域内设备位置数据的地理围栏搜查令（geofence warrants）需受第四修正案保护，必须基于可能原因取得搜查令。大法官埃琳娜·卡根（Elena Kagan）撰写了多数意见，指出此类搜索即使在公共区域也侵犯了合理的隐私期待。 这项里程碑式裁决限制了执法部门未经授权大规模收集位置数据的行为，加强了数百万智能手机用户的数字隐私权。它为限制被广泛批评为违宪的大规模搜索的反向位置搜索设立了先例。 法院驳回了政府关于地理围栏搜查令因结果范围狭窄而足够有限的论点，认为从类似 Google Sensorvault 的大型数据库中初步收集数据即构成搜索。意见强调，执法部门不得在未描述嫌疑人的情况下翻查海量位置数据。

hackernews · cdrnsf · Jun 29, 15:54 · [社区讨论](https://news.ycombinator.com/item?id=48720924)

**背景**: 地理围栏搜查令（又称反向位置搜查令）允许警方搜索公司数据库中在特定时间位于某地理区域内的所有设备。Google 的 Sensorvault 存储了数亿用户的历史位置数据，成为此类搜查令的主要目标。第四修正案保护公民免受不合理搜查和扣押，该裁决明确了批量收集位置数据属于该保护范围。

## [WATaBoy：将 Game Boy 指令即时编译为 WASM，性能超越原生解释器](https://humphri.es/blog/WATaBoy/) ⭐️ 8.0/10

一篇博客文章介绍了 WATaBoy，这是一个即时（JIT）编译器，将 Game Boy CPU 指令翻译成 WebAssembly（WASM），在相同模拟工作负载下实现了比原生解释器更快的性能。 这表明将 JIT 编译到 WASM 在模拟中能超越原生解释器，为在 Web 环境和有 JIT 限制的平台（如 iOS）上实现高性能模拟开辟了新可能性。 性能基准测试比较了 WATaBoy 的 JIT 编译器在 WASM 中运行、其解释器在 WASM 中运行、以及其解释器原生运行，三者模拟相同的 Game Boy 标题画面循环 10 秒真实时间；Firefox 比 Chrome/Safari 慢约 25%。

hackernews · energeticbark · Jun 29, 15:02 · [社区讨论](https://news.ycombinator.com/item?id=48720190)

**背景**: 模拟器通常使用解释或即时（JIT）编译将客户机指令翻译为主机机器码。JIT 通常能提升速度，但需要编写动态代码生成器。WebAssembly（WASM）是一种面向 Web 浏览器的低级二进制格式，支持 JIT 编译，但传统上在某些平台（如 iOS）上 JIT 受限，除了在 Web 浏览器内。WATaBoy 利用 WASM 在浏览器内的 JIT 能力来实现高性能。

## [CUDA 内核启动揭秘：从 CPU 到 GPU 的路径](https://fergusfinn.com/blog/what-happens-when-you-run-a-gpu-kernel/) ⭐️ 8.0/10

Fergus Finn 的博客文章详细逐步解释了 CUDA 内核从 CPU 启动到 GPU 执行所经过的硬件和软件路径，涵盖了门铃机制、队列元数据（QMD）和线程束调度。 这篇深入解读揭示了 GPU 计算中一个关键但通常不透明的部分，帮助开发者通过理解底层提交过程来编写更高效的 CUDA 代码。它弥合了高级编程与硬件行为之间的鸿沟。 文章解释了 CPU 如何通过环形缓冲区向推送缓冲区写入命令、摇响门铃通知 GPU，以及 GPU 的工作分配器读取 QMD 来启动线程块。线程束的合格性由指令就绪状态和资源可用性决定。

hackernews · mezark · Jun 29, 13:11 · [社区讨论](https://news.ycombinator.com/item?id=48718863)

**背景**: CUDA 是 NVIDIA 面向 GPU 的并行计算平台和编程模型。当 CUDA 内核启动时，主机 CPU 必须通过命令队列将启动参数传递给 GPU。门铃是一种硬件机制，用于通知 GPU 获取新命令；QMD 是一种描述符结构，包含网格尺寸、内核参数和资源需求。线程束调度是 GPU 选择接下来执行哪一组 32 个线程的方法。
