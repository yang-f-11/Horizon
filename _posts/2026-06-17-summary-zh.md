## [停止在浏览器会话中使用 JWT](https://gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) ⭐️ 8.0/10

一篇广泛传播的 gist 和社区讨论指出，不应在基于浏览器的用户会话中使用 JSON Web Tokens（JWT），原因是存在安全和撤销问题。讨论澄清，JWT 适用于服务间通信，但不适合客户端会话。 这很重要，因为许多 Web 开发者默认使用 JWT 进行身份验证，却不了解其局限性。采用基于会话的身份验证和 httpOnly cookie 可以提高安全性，降低 XSS 风险，并简化令牌撤销。 JWT 是无状态的，一旦签发就无法轻易撤销；它们设计用于非常短的寿命（≤5 分钟）。对于浏览器会话，将状态化会话 ID 存储在 httpOnly cookie 中能提供更好的撤销控制，并且不易受到 XSS 攻击。

hackernews · dzonga · Jun 16, 16:49 · [社区讨论](https://news.ycombinator.com/item?id=48558147)

**背景**: JWT 是一种自包含的令牌格式，携带声明并经过数字签名。与服务器存储会话状态的基于会话的身份验证不同，JWT 验证只需要令牌本身。然而，这种无状态特性使得在没有黑名单的情况下无法立即撤销令牌。讨论对比了无状态 JWT 与状态化会话，后者的会话 ID 存储在服务器端，可以即时撤销。
