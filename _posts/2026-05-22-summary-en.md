## [Freenet Redesign: Decentralized Apps with WebAssembly Contracts](https://freenet.org/) ⭐️ 8.0/10

The new Freenet is a ground-up redesign of the original peer-to-peer platform, now using WebAssembly contracts to define a global decentralized key-value store, with decentralized apps like group chat (River) and CMS (Delta) already running. This redesign revives a historic P2P project with a novel architecture that treats keys as executable contracts, potentially enabling flexible decentralized applications without blockchain overhead. The unique commutative merge approach offers fast state synchronization, which could lower barriers for building P2P apps. Each contract includes a merge operation that must be commutative, allowing state updates to propagate like a virus and achieve consistency in seconds. Applications run as single-page web apps that connect to a local Freenet peer via WebSocket.

hackernews · sanity · May 21, 14:34 · [Discussion](https://news.ycombinator.com/item?id=48223362)

**Background**: Freenet was originally created in the early 2000s as an anonymous peer-to-peer file-sharing network, later renamed Hyphanet. The redesigned Freenet uses WebAssembly (WASM), a low-level binary format that runs efficiently in web browsers, to define smart-contract-like logic for data storage and mutation. The commutative merge approach is similar to Conflict-free Replicated Data Types (CRDTs), which allow multiple peers to update data concurrently without conflicts.

## [Local Video Indexing with Gemma 4-31B on a MacBook](https://blog.simbastack.com/indexed-a-year-of-video-locally/) ⭐️ 8.0/10

A developer indexed a full year of personal video footage locally on a 2021 MacBook using the multimodal Gemma 4-31B model, leveraging 50GB of swap memory to handle the model's memory requirements, and shared the code and insights in a blog post and on GitHub as the 'framedex' project under MIT license. This demonstrates that advanced AI video indexing can be done entirely on consumer-grade hardware without cloud dependence, making personal archive management more accessible and private. It also showcases the practical capabilities of the open-weight Gemma 4 model on memory-constrained devices. The project uses Gemma 4-31B at 4-bit quantization, which typically requires ~19 GiB of memory, but the author observed 28.4 GiB usage and 50GB swap due to image inputs and system overhead. A community member (Confiks) questioned the necessity of such heavy swapping, noting it can accelerate SSD wear and that Gemma 4 31B at 4-bit should be around 19 GiB.

**Background**: Gemma 4 is a family of open-weight multimodal models from Google DeepMind, capable of processing text and image inputs to generate text outputs. Running large language models locally requires significant RAM; when RAM is insufficient, the operating system uses swap memory on the SSD, which can degrade performance and wear out the drive over time. This project shows a practical application of using a modern open model on a standard laptop for real-world video analysis.
